# An eval account is the default, and a person may record in their own account

Onboarding offers two modes. Dedicated account mode, the recommended one, records in an eval account. Mixed account mode, a clearly labeled second choice ("Try it out"), records work blocks in a macOS user account the person also uses for other things. The eval account stays the default because everything captured in it is eval activity, so there is little risk of recording personal work, and because it keeps the eval apart from the person's other files and sign-ins. We add mixed account mode because a work block can be started and stopped, so a person can fairly ask to see what goodall shows about their own work with AI before making an account for it. Requiring an eval account for every use (ADR 0008's position) was rejected as too high a price for a first look. The risk mixed account mode brings is consent drift: forgetting that a work block is active and capturing personal activity. Consent is therefore carried differently in the two. In dedicated account mode goodall starts a work block when the person signs in, and the account itself is the consent boundary: signing in means recording. In mixed account mode nothing starts unless the person starts it, and goodall adds safeguards against forgetting. In both, a menu bar icon shows for as long as the person is signed in whether goodall is recording (ADR 0024), and goodall shows a notification whenever a work block is started or stopped by something other than the person's own command, because that is the one moment the person does not already know. "Record" is the verb goodall uses with people for what it does, chosen because it is the clearest word for consent.

## Consequences

- ADR 0008 holds with one change: a macOS user account still holds at most one eval, but that account need no longer be an eval account. The eval account's rules (standard, non-admin, used for nothing else) apply in dedicated account mode only. In mixed account mode `goodall doctor` warns, and does not fail, when the account is an administrator account.
- A mixed account trial is a real eval. It uses the same records and commands, the mode is written onto every work block as an observation, and every export is stamped with it, so an analyst can always tell the two modes apart.
- A background start or stop is one made by signing in or out, by a schedule or script, or by goodall itself ending a work block. Each shows a notification. A start, pause or stop the person chose shows none.
- Goodall may now end a work block in the background, which it never did before. The promise becomes: goodall never ends a work block without telling you. In dedicated account mode signing out stops the work block. Switching to another account and closing the lid do not, because agents keep working in an account that was switched away from. The three-hour idle limit stays as the backstop.
- Pause ends the work block, and recording again starts a new one that names the one it continues. There is no paused state inside a work block: a paused account is simply not recording, so in dedicated account mode the prompt gate is closed. An agent session that spans a pause is still copied whole, because copies are byte for byte (ADR 0019).
- The words a person sees are "Record work block", "Pause" and "Stop recording". The menu bar icon and the notifications never say "eval"; the setup page and the docs do, with one plain sentence on first use saying what it means.
- Mixed account mode differs from dedicated account mode in three ways, each because the existing behavior assumes an eval account. The prompt gate is off: the hooks only leave heartbeats and copy transcripts while a work block is active, and work outside one is left uncaptured. ActivityWatch is left out in the first version, because it records the whole account all the time (ADR 0016). Any agent session with a record inside a work block is still copied whatever it was about (ADR 0019), and the setup page says so in plain words.
- Mixed account mode has an automatic timeout, on by default; in dedicated account mode it is off by default. The length is asked on the setup page. It counts from when the work block started, not from the last activity, because the risk it guards against is recording while busy with something personal, which looks like activity. A notification a few minutes before offers "Keep recording".
- A person can delete what one work block captured. Deleting removes the raw and derived records whole and never edits one, so raw records that remain are still verbatim (ADR 0003). The work block's own record is replaced by one saying only that a work block was deleted at the person's request, and when; local git history is left alone, so the fact of the deletion stays honest. Deleting is a typed command with an explicit confirming flag, because the menu bar icon never asks a question.
- Onboarding says plainly that the data is local. Nothing is uploaded: raw records never leave the Mac (ADR 0017) and the record repo is never pushed (ADR 0023). A person shares only by making an export.
