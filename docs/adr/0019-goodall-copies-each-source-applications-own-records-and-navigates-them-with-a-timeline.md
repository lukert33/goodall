# Goodall copies each source application's own records, and navigates them with a timeline

Goodall captures agent sessions itself, from more than one source application, and is not built on Entire. For every source application the baseline is the same: at `goodall stop`, and on the next start for a work block nobody closed, goodall copies the application's own session files into the log directory, byte for byte. An agent session belongs to a work block when any of its records carries a time inside the block, and every agent session in the eval account counts, whatever folder it ran in, because the eval account is the boundary of the eval. On top of the copies goodall builds a timeline: a derived SQLite database, one per eval, in the log directory, that goodall can delete and rebuild at any time. A timeline entry holds only times, numbers and values from fixed lists (actor label, kind of action, tool name, application name), plus a pointer to its place in a raw record. Anything a person or a website could have written, including window titles, page addresses, file paths and workstream names, stays in the raw record and is fetched from there when a person looks.

We rejected building on Entire because its checkpoints are edited copies that exist only where a commit follows the agent's work (`docs/related-work.md`), and raw records must be verbatim (ADR 0003). We rejected relying on hooks for every source application: Claude Code's hooks give goodall the prompt gate and heartbeats, but the other applications offer no dependable equivalent, and a baseline that needs nothing from the application is the one that carries to the next application. We rejected keeping the raw records inside the database, which would break the verbatim rule, and rejected a timeline of plain files, because the questions an eval asks run across weeks and across applications. We rejected copying prose into the timeline because most leaks in shared chat datasets came from free text that an automated pass failed to find (`docs/research/privacy/wildchat-redaction-case-study.md`); a timeline with no prose leaves a release nothing to scrub.

## Consequences

- The first version targets three app families, in this order: the Claude family (the desktop app's Code tab and Claude Code in a terminal, which write the same files), then the Antigravity family, then the Codex family. The Claude family must work. Each of the other two has a one-day limit and may add no dependency; a family that does not fit is dropped from the first version.
- The prompt gate, heartbeats and telemetry stay as they are and remain extras that only Claude Code has. Work done in another source application outside a work block is not refused; it is left uncaptured.
- A record is copied as its application wrote it. What a record is known to lack (Antigravity's record has no system prompt; Codex's reasoning is encrypted) is documented per source application, and goodall reconstructs nothing.
- Antigravity keeps each conversation twice, as a SQLite file and as a JSONL transcript beside it. Goodall copies both and reads the JSONL, so the fuller record is kept if the JSONL proves incomplete.
- ADR 0015's layout, where the log directory mirrors Claude Code's projects folder, now describes one source application among several. Each application's records keep that application's own layout under the log directory.
- The timeline is near-exportable but is never exported as it stands. A release (ADR 0017) still drops the pointers, which are file paths, replaces ids, and coarsens times.
- After the first version, `goodall export scout` builds from the timeline, so every app family reaches Scout through one shape. Inspect and Scout stay an optional install.
- The log directory's name ends in `.noindex` so Spotlight does not list goodall's copies among a person's own files. `goodall doctor` warns when Spotlight can find anything inside it. That the convention works is to be confirmed on a real Mac before it is relied on.
- Cowork and plain chat in the Claude desktop app are not captured in the first version. Their sessions are kept in the person's Claude account, not on the Mac, and goodall makes no network calls and holds no credentials. Whether a step that copies the app's own export is worth building is decided after one trial export.
