# A work block is corrected by a fix recorded beside it

When goodall cannot tell which workstream a work block was for, because its marker was damaged, it still records the block, with the end state `abnormal` and the reserved workstream `unknown`, which no eval may use for a real workstream: the owner would rather keep logged activity with an ambiguous value and reconcile it later than lose it. Records are never rewritten (ADR 0003), so the reconciliation is a new record, a work block fix, written by `goodall fixblock <work block id> --workstream NAME` into the record repo's `work-block-fixes/` folder; it names the work block and gives the corrected value, and analysis reads the two together through one function that returns each work block's effective workstream, the latest fix winning. Editing the work block record in place was rejected because it would break the verbatim record and hide that anything changed; a general amendment record for any field of any record was rejected as wider than the need. A fix always concerns one work block, and each value it can correct is an optional field named as in the work block record, so a later value (a start time, say) is another optional field and another option on the command, not a new record type. Fix files are kept for good once an eval holds data, so this shape is hard to change.
