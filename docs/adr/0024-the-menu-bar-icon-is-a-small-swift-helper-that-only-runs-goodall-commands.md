# The menu bar icon is a small Swift helper that only runs goodall commands

Goodall puts one icon in the Mac's menu bar, in both dedicated and mixed account mode (ADR 0021). It is the recording indicator, with three looks for recording, paused and not recording, and its menu is the easy way to control goodall without a terminal: "Record work block" with a list of workstreams, "Pause", "Stop recording", "Settings…" and "Quit goodall". The icon is a small helper program written in Swift, shipped inside goodall's package and started at sign-in. The same helper shows goodall's notifications. It holds no logic: it reads state from goodall and each menu item runs one `goodall` command, so everything a researcher needs to understand stays in the Python. A menu bar icon cannot be made with the Python standard library. We compared the alternatives on 2026-11-26. PyObjC would keep everything in Python, but it adds two compiled packages from a single maintainer, and its notifications fall back to `osascript`, which shows them as coming from Script Editor and often drops them silently; for a consent signal that is not good enough. rumps and xbar are no longer maintained. SwiftBar is a separate application an administrator would have to install. A helper of our own adds no Python dependency and shows notifications under goodall's own name. The cost we accept is a second language in the repository and a compiled piece to build and sign.

## Consequences

- Picking a menu item is giving a command with an argument, the same as typing `goodall start engineering`. The icon never asks a question, so the setup page stays the only place goodall asks a person for answers (ADR 0012). "Settings…" opens the setup page in the browser with the current answers filled in, which is how a person registers a new workstream; there is no settings window.
- The menu and the notifications never say "eval" (ADR 0021).
- "Quit goodall" stops any recording cleanly, as if the person chose "Stop recording", then removes the icon. Nothing records while the icon is gone: in dedicated account mode the prompt gate is closed. The icon returns at the next sign-in or when the person runs `goodall start`.
- If the helper dies, no work block is ended or damaged, and the LaunchAgent that started it brings it back.
- The Swift source is kept small and commented for a reader who does not know Swift, and the rule that the hook path is standard-library Python is untouched: no hook starts or waits for the helper.
- Three things are confirmed by a spike before anything is built on this (`goodall-fs9.29`): that a helper with only a local signature, installed with goodall, runs in a standard account; that it can get notification permission there; and that it starts cleanly at sign-in. If any fails, PyObjC is the fallback and goes through the dependency request in `AGENTS.md`.
- How the helper is built for a release, and whether goodall's package then differs between Macs, is decided with the spike's findings. Goodall already supports only Macs with Apple chips.
