# A secrets manager is required whenever a secret exists

Every credential goodall refers to must be a reference into 1Password or an equivalent secrets manager, resolved at the moment of use; raw secret values are rejected as input and never written to a file. "Equivalent" means a manager that keeps the value out of files and can launch a program with the secret already in its environment, so the value never passes through goodall (ADR 0010). Allowing plain values with a warning would lower the barrier for small teams, but goodall is meant to enforce a strong secret-storage posture from the first moment: a secret must not be able to end up in a file, a shell history or a transcript an agent can read. 1Password, through its `op://vault/item/field` references, is the only manager supported today; supporting others is a reasonable way to make goodall useful to more researchers, and is welcome as long as it meets the same bar. The requirement applies only when a secret exists, so an eval with no credentials needs no secrets manager.
