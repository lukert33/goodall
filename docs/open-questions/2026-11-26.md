# Open questions, 2026-11-26

Written for the project owner while his notes "Goodall onboarding & session consent — UX notes" (2026-11-26) were worked into the plans. Those notes are recorded as ADR 0021 (an eval account is the default, and a person may record in their own account) and ADR 0022 (the administrator install creates the eval account and stages its first sign-in setup), as new terms in `GLOSSARY.md`, and as Beads issues under the setup and capture epics. This document holds what the notes left open and every place they meet a decision already made.

**How to read it.** Section 1 needs his answer. Section 2 is good enough to keep building on and is listed so he can overrule it cheaply. Numbers continue from `docs/open-questions/2026-11-16.md`, so each can be referred to in conversation.

Status: answered. The owner answered every question in a grilling session in chat on 2026-11-26; each answer is written under its question. The same session added the menu bar icon (ADR 0024) and made the record repo local (ADR 0023). "Own-account mode" in the questions below was renamed mixed account mode; the questions are left as they were asked.

## 1. Needs the owner

### What the notes contradict

- **Q70. "Nothing is uploaded, ever, unless you export it" is not true of the record repo today.** The notes say no automated upload, metadata included, is built or planned. But goodall commits and pushes work blocks, journal entries and interventions to the record repo's remote whenever one is set (invariant 6, ADR 0001), and `goodall status` can push too (Q49). Those records hold times, workstream names and a person's own written notes. Raw records are not affected: they never leave the Mac (ADR 0017). `goodall-9nf` already asks for the remote to be optional. *Recommendation: no remote unless the person sets one up, never one in own-account mode, and the onboarding sentence becomes "Nothing leaves this Mac unless you export it or you choose to share your record repo." The shorter sentence in the notes can only be used if pushing stops being automatic.*
  - **Answer (2026-11-26):** the record repo is never pushed at all, so the short sentence is true. Every reference to a remote is removed, and `gh` goes with it (ADR 0023, `goodall-g1k.5`).
- **Q71. "Session" in the notes, "work block" in the glossary.** The notes speak of starting, stopping and recording "a session". The glossary reserves that word: a work block is the stretch that is started and stopped, and an agent session is one conversation inside it. I have read every "session" in the notes as a work block and kept the verb "record". *Recommendation: keep "work block" in code, records and docs. Decide separately whether the words shown to a person on the setup page and in notifications say "recording" alone ("Recording started") and so avoid both nouns.*
  - **Answer (2026-11-26):** "work block" stays, and "eval" stays as the name for the record of a project's making. A person sees "Record work block", "Pause" and "Stop recording"; he chose "work block" for the menu because it points the person at their work. The menu and notifications never say "eval".

### Own-account mode

- **Q72. The prompt gate in a person's own account.** Goodall's hooks go in the account's Claude Code settings, and the gate refuses every prompt while no work block is active. In an eval account that is deliberate (ADR 0020 keeps it). In a person's own account it would refuse all of their ordinary Claude Code work. *Recommendation: in own-account mode the gate is off and the hooks only leave heartbeats and copy transcripts while a work block is active. Work outside a work block is left uncaptured, as it already is for the other source applications (ADR 0019).*
  - **Answer (2026-11-26):** agreed. Off in mixed account mode.
- **Q73. ActivityWatch in a person's own account.** ActivityWatch records the whole account all the time, and goodall copies everything it holds since the last copy (ADR 0016). In a person's own account that would copy window titles and page addresses from their personal time into the log directory. *Recommendation: own-account mode does not include ActivityWatch in its first version. Later, copy only the time ranges of work blocks; ActivityWatch's event requests take a start and an end.*
  - **Answer (2026-11-26):** agreed. ActivityWatch is left out of mixed account mode in its first version.
- **Q74. Personal agent sessions inside a work block.** Every agent session with a record inside a work block is copied, whatever folder it ran in, because the eval account is the boundary (ADR 0019). In a person's own account an unrelated conversation held during a work block is copied too. This is the consent drift the notes name. *Recommendation: accept it, say it in plain words on the setup page, and rely on the recording indicator and on deleting a work block's data. Limiting copies to folders in the declared scope is the alternative, at the cost of missing work done elsewhere.*
  - **Answer (2026-11-26):** agreed. Accept the copy and say so plainly on the setup page.
- **Q75. Is a trial a real eval?** Own-account mode could produce records that are later exported and pooled with others, or it could be only a private look. The first needs the mode written onto each work block so an analyst can tell the two apart; the second could skip the roster, the record repo's remote and the construct. *Recommendation: the same records and commands, a record repo with no remote, the mode written onto every work block as an observation, and exports stamped with it.*
  - **Answer (2026-11-26):** agreed. A trial is a real eval, with the mode on every work block and export.
- **Q76. `goodall doctor` in a person's own account.** Its account check fails for an administrator account, and most people's own account is one. *Recommendation: in own-account mode the check is a warning that says an eval account is the recommended setup, not a failure.*
  - **Answer (2026-11-26):** agreed. A warning, not a failure.
- **Q77. Automatic timeout (from the notes).** Should it be on by default in own-account mode, and for how long? *Recommendation: on by default, with the length asked on the setup page and a notification a few minutes before it stops the work block. Two hours is a guess at a default, not a researched figure. Off by default in an eval account, where signing in means recording.*
  - **Answer (2026-11-26):** agreed, and the limit counts from when the work block started, not from the last activity. The warning offers "Keep recording".
- **Q83. What deleting a work block's data removes.** The raw copies in the log directory and anything derived from them can simply be deleted. The work block's own record is a commit in the record repo, so it stays in git history, and on a remote if one was ever pushed to. *Recommendation: delete the raw and derived records, replace the work block's record with one saying it was deleted at the person's request and when, and leave git history alone. With no remote in own-account mode (Q70), nothing has left the Mac.*
  - **Answer (2026-11-26):** agreed. Deleting is a typed command with a confirming flag, shown by `goodall logs`, and stays out of the menu.

### Notifications and the indicator

- **Q78. The form of the recording indicator (from the notes).** A menu bar icon needs a program that stays running and draws with macOS's own interface libraries, which the Python standard library cannot do; it would mean a new dependency or a small helper written in another language, each needing the provenance check. I have not tested any option. *Recommendation: a spike (`goodall-fs9.29`) that compares a menu bar helper with what needs no dependency, before choosing.*
  - **Answer (2026-11-26):** a menu bar icon, which is also the control for starting, pausing and stopping (ADR 0024). The spike `goodall-fs9.29` now confirms the chosen design instead of comparing options.
- **Q80. How a notification is sent.** macOS's `osascript` can show one with no new dependency and fits the runner. From memory, not tested here: the notification is shown as coming from Script Editor, and a Focus mode can hide it. For a consent signal a hidden notification matters. *Recommendation: build on `osascript` first, and settle it in the hand test.*
  - **Answer (2026-11-26):** not `osascript`. Research the same day found its notifications show as Script Editor and are often dropped. The menu bar helper sends them under goodall's own name (ADR 0024).

### Accounts and sign-in

- **Q79. FileVault (from the notes).** On a Mac with FileVault, does an account made with `sysadminctl` get a secure token, so it can unlock the disk at startup? The person also needs one first sign-in to finish macOS's own setup screens. *Only a hand test answers this (`goodall-ayy.11`).*
  - **Answer (2026-11-26):** still open; only the hand test answers it.
- **Q81. What stops a work block that sign-in started.** Signing out is the natural end, but switching to another account without signing out leaves the eval account signed in and the work block active, and closing the lid is neither. Today an unclosed work block gets an inferred end from its last heartbeat. *Recommendation: keep the inferred end as the rule, add a stop at sign-out if macOS lets a LaunchAgent do one dependably, and find out in the hand test.*
  - **Answer (2026-11-26):** signing out stops the work block. Switching accounts and closing the lid do not, because agents keep working in an account that was switched away from. The idle limit stays as the backstop.
- **Q82. How the setup answers reach the first sign-in.** The first-run script cannot ask anything in the terminal (ADR 0012). *Recommendation: the setup page is answered in the administrator account, the administrator install stages the answers file where only root can change it, and first sign-in setup is the unattended path ADR 0012 already has. The answers file holds no secret values, by the existing check.*
  - **Answer (2026-11-26):** agreed.
- **Q84. Goodall running privileged commands.** Creating an account and writing into `/Library/LaunchAgents` both need administrator rights. The notes have the install script do this. Until now goodall has only guided administration and left the acting to people (invariant 6 says so for git remotes). *Recommendation: goodall runs each privileged command through the runner with the terminal handed over, so macOS asks for the administrator password itself and goodall never sees it, after showing every planned change. Invariant 6 keeps its meaning for git; AGENTS.md gains a line when this is built.*
  - **Answer (2026-11-26):** agreed.

## 3. Decided in the same session, beyond the questions above

- **D1. The menu bar icon.** One icon is the recording indicator and the control, in both modes: "Record work block" with a list of workstreams, "Pause", "Stop recording", "Settings…" and "Quit goodall". The owner approved the designs shown in chat. Quit stops any recording cleanly and removes the icon until the next sign-in or `goodall start`. It is a small Swift helper, confirmed by a spike first (ADR 0024, `goodall-fs9.29`, `goodall-fs9.34`).
- **D2. Pause.** Pause ends the work block, and recording again starts a new one that names the one it continues (ADR 0021, `goodall-fs9.35`).
- **D3. Background stops.** Goodall may end a work block in the background, always with a notification. `docs/work-block-endings.md` says today that it never does, and is rewritten when this is built (`goodall-fs9.28`).
- **D4. Settings.** "Settings…" reopens the setup page with the current answers filled in, for example to register a new workstream. No settings window (`goodall-ayy.13`).
- **D5. "Eval" stays, and "project" gets a meaning.** The owner considered dropping "eval" as loaded, and kept it: the project is the work output, made for the outside world, and the eval is the record of its making, which ties back to open-world evals. `GLOSSARY.md` now defines "project" that way.
- **D6. One person's record.** An eval is one person's record on one Mac. The contributor id stays on every record so that several people's records can be associated later, between exports (ADR 0023).
- **D7. Left for their own pull requests.** Removing the push and `gh` code, and updating `README.md`, `docs/DEPENDENCIES.md` and `docs/work-block-endings.md`, which describe built behavior and change with the code (`goodall-g1k.5`).
